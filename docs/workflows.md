# Workflows

## Proceso de creación de un release

Flujo canónico del sello. Tres fases: **input → construcción conjunta → output**.

```text
contacto  →  construcción conjunta  →  digital + web expandida + físico
                                              └─ evento (opcional)
```

### 1. Input — contacto

Se abre el proceso de una de estas dos formas:

- **strlac contacta** a un artista candidato
- **un artista contacta** a strlac

En ambos casos el punto de partida es una conversación de curaduría, no un formulario de “submit demo” genérico.

Checklist de apertura:

```text
Contacto
- [ ] Origen: [ ] strlac → artista  [ ] artista → strlac
- [ ] Artista / alias:
- [ ] Referencias / links escuchados:
- [ ] Por qué encaja (1–3 líneas curatoriales):
- [ ] Primera conversación hecha:
- [ ] Interés mutuo en construir juntos: sí / no / pendiente
```

### 2. Construcción conjunta del proyecto

El release no se “recibe listo”: se **arma entre el sello y el artista**.

En esta fase se define el concepto, las capas del proyecto y qué entra en cada output (digital, web, físico, evento).

Checklist de construcción:

```text
Construcción conjunta
- [ ] Concepto / tesis del proyecto (1 párrafo):
- [ ] Formato sonoro (álbum / EP / live / research / compilado…):
- [ ] Qué aporta el artista:
- [ ] Qué aporta strlac (curaduría, web, edición, difusión…):
- [ ] Alcance de la web expandida:
- [ ] Alcance del físico (objeto, tirada, lógica):
- [ ] ¿Hay evento? no / sí — nota:
- [ ] Idiomas del copy: ES / EN / ambos
- [ ] Créditos previstos:
- [ ] Restricciones del artista:
- [ ] Fecha objetivo (si hay):
```

### 3. Output — tres entregables (+ evento opcional)

Todo release strlac apunta a **tres salidas**. El evento es opcional.

| # | Output | Qué es |
|---|--------|--------|
| 1 | **Release digital** | Audio publicado (p. ej. Bandcamp) + copy + artwork |
| 2 | **Web expandida** | Capa online del proyecto (micrositio, código, recorrido, score, etc.) |
| 3 | **Físico** | Objeto / edición material limitada |
| — | **Evento** *(opcional)* | Presentación, live, karaoke, listening, etc. |

#### 3.1 Release digital

```text
Digital
- [ ] Masters + metadatos
- [ ] Cover 3000×3000 (+ thumbnail legible)
- [ ] Copy Bandcamp (ver voz.md)
- [ ] Banner / OG si hace falta
- [ ] URL Bandcamp
- [ ] Published / scheduled
```

#### 3.2 Web expandida

```text
Web expandida
- [ ] Concepto de la capa web acordado
- [ ] URL / micrositio
- [ ] Repo o fuente (si aplica)
- [ ] Integración con el digital (link cruzado Bandcamp ↔ web)
- [ ] Still / capture para redes y docs
```

#### 3.3 Físico

```text
Físico
- [ ] Tipo de objeto (polaroid, merch, score impreso…):
- [ ] Tirada:
- [ ] Producción / logística
- [ ] Foto del objeto
- [ ] Cómo se vincula a la compra digital (si aplica)
```

#### 3.4 Evento (opcional)

```text
Evento
- [ ] ¿Se hace? no / sí
- [ ] Formato (live, listening, karaoke, instalación…):
- [ ] Lugar / fecha:
- [ ] Relación con digital / web / físico
- [ ] Pieza de difusión
```

## Intake unificado (para automatizar)

Cuando el proyecto ya está en construcción o listo para producir, completar:

```text
Release intake
- [ ] Título canónico:
- [ ] Artista / alias:
- [ ] Origen del contacto: strlac→artista / artista→strlac
- [ ] Concepto (1 párrafo):
- [ ] Fecha de salida:
- [ ] Catálogo / ID interno (si existe):
- [ ] Digital: formato + URL Bandcamp
- [ ] Web expandida: alcance + URL + repo
- [ ] Físico: objeto + tirada
- [ ] Evento: no / sí — detalle
- [ ] Idiomas del copy: ES / EN / ambos
- [ ] Créditos y agradecimientos:
- [ ] Assets existentes (carpeta):
- [ ] Restricciones del artista:
```

## Copy y publicación

- Visual: [visual.md](visual.md).
- Al cerrar: actualizar [catalogo.md](catalogo.md) y strlac.xyz si corresponde.
- Networking: [networking.md](networking.md).

## Orden operativo

```text
contacto
  → construcción conjunta (definir las 3 salidas + evento?)
  → producir digital + web + físico (en paralelo cuando se pueda)
  → evento (si hay)
  → difusión
  → actualizar catálogo / docs
```
